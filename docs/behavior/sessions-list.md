# Sessions list: filtered, grouped and sorted history

Draft by Claude, not corrected by Jesse. From the old app (mac-command-bar 2089290, `myWorkViewOptions.ts`,
`sessionRailStore.svelte.ts`) and parity map section 1, updated for the main-screen spec's sessions column (S1 to S4,
PR 1). Owner correction, 28 October 2026: started sessions are ordinary rows; native sub-agents are excluded; view changes start at the top. Rail parity with the old app is partial: the row menu keeps only the lifecycle moves, and Answer, Rename, pin,
copy and Delete come later.

- sessions-list#1: Every ordinary session is Working, Done or Settled, from its completion and settlement times. The rail lists every lifecycle by default. Group by Status adds Working, Done and Settled sections in that fixed order, with each section's filtered count. Running remains a row state for a turn or background work that outlives it; Needs you remains a row state for an open question or permission. An unread answer alone isn't Needs you, and the user's Working mark isn't Running. A new session is in Working.
- sessions-list#2: The user moves a session with its row's menu: Mark done, Settle, Back to working (and Unsettle, which puts it back in Done).
- sessions-list#3: Only that menu moves a session. Nothing is inferred from its processes, a finished turn or a new prompt.
- sessions-list#4: Done keeps when it was first marked done; settling or unsettling doesn't change that time. Back to working clears both times.
- sessions-list#5: The backend keeps the mark and stamps the time from its own clock, so every window shows the change at once. A remote session's mark is kept on this desktop.
- sessions-list#6: The default groups by Project only. Group by can independently add Status, keep Project, or choose None for one flat list. Status sections stay Working, Done, Settled; projects stay A to Z with no project last. Sort changes only rows inside a group, or the flat list: Recent activity defaults to Newest first and Name defaults to A to Z, with the opposite direction available. Name sorts by the name the row shows: its title, or its project's folder name before it has one. The session id breaks ties. A project spans machines and names each one. A session started with start_session is an ordinary counted row, at the same left edge: its own lifecycle, project and sort values place, group, filter and count it like any other row, and it keeps its own Running and Needs you state. Native sub-agents never appear or contribute to counts.
- sessions-list#7: Pills narrow the rail by Provider, Location (Local or Remote) and Status (Working, Done or Settled); no Status picks includes all three. Clicking a group shows "← Back" and values that toggle several at once; a picked group reads its picks joined by "/", or "All"; "← Back", Escape or a click outside closes the group and keeps the picks; a round × clears every group. Picks are saved and return at start, including older saved values without Status. The text filter narrows by title or project; Escape or opening a session clears it. A selected session filtered out stays open.
- sessions-list#8: Each project's header has a New session button that opens the new-session form with that project's folder and machine filled in.
- sessions-list#9: Section and project counts are the backend's after filters and before paging. Their headers take a place in the page and a chevron folds that group in this window only; nothing starts folded. A view change starts at the top. The rail loads the next page near its end and earlier entries when scrolling back. On change at the top of the list it reads from the top, so new and moved rows come in under their headings; further down it reads around the current row so that row stays in view; a filtered or folded row falls back to the cursor. Folding or unfolding reads around that group's header, so it stays where it was.
- sessions-list#10: Each row shows the first state that holds: it needs you (an open question or permission, with "needs you" by its agent), it is working, its last turn failed, a turn ended unseen, or nothing. Opening the session counts as seeing it, as does a turn ending while open. A line under the pills shows the backend's filtered `Needs` total, "N need you", at its right end, when it is above zero.
- sessions-list#11: A remote session whose machine isn't answering shows "offline" on its row, ahead of what it was doing, and its chat disables Send and Stop and says the machine is offline, before anything is tried. Both come back when the machine answers again.
- sessions-list#12: An offline session's chat has a Connect button beside its offline line, as the old app had. It starts the ssh tunnel again at once if it's waiting to, and checks the machine now, again every half second while nothing answers, for up to 10 seconds; it reads "Connecting…" meanwhile. If the machine answers, the line goes and Send and Stop come back; if not, the line says it still didn't answer.
