## 0. Findings that change the picture (read these first)

1. **The remote's `/socket` serves no features today.** `Assembly.Remote/Serve/ServeRun.cs:51` builds `ApiServices` without the `Features` argument, so `ApiServer.cs:56` (`services.Features ?? []`) registers nothing. Only `DesktopBackend.cs:90-96` passes the feature list. So every socket call in section 2 exists only on the desktop; C2 needs the remote to register them too (same `IFeature` classes, passed in `ServeRun.cs:51`). verified
2. **The socket client gets a `welcome` with `protocol` and `machine` only** (`Infrastructure/Socket/SocketConnection.cs:150`, `SocketFrames` WelcomeFrame). There is no row `formatVersion`/commit on it, and no socket call for it. `RemoteMachine.CheckFormatAsync` (`Remote/RemoteMachine.cs:180-188`) needs `formatVersion` (`Infrastructure/Http/InfoRoutes.cs:67`), and check4 needs `commit` (`scripts/check4.sh:71-72`). verified
3. **The `sessions` topic item has no helper flag** (`Application/Features/Chat/Sessions/SessionItem.cs:6-7`: sessionId, agent, repoUrl, title, machine, parentSessionId, acpSessionId, updatedAt). `RemoteMachine` stores helpers with `helper: true` (`RemoteMachine.cs:55`, `:80`). The relay would need this field, or the subagent row (which carries `helper`, `RemoteMachine.cs:55`) keeps doing that job. verified
4. **No socket call exists for the helper outbox** (`/outbox` x3). Section 3.
5. **`RemoteMachine` keeps ONE `HttpClient` per remote plus one `/live` WebSocket per session** (`RemoteMachine.cs:40`, `RemoteFollower.cs:83-86`). C2's "one socket per remote" replaces both.
6. **Rows catch-up gap.** The `rows` topic resumes at most `RowsFeature.PageLimit` = 500 rows (`Rows/RowsFeature.cs:20`, `:51`) or `CatchUpBytes` = 8 MB (`:26`); further behind it snapshots at the last seq with no rows (`:54`). `/live?after=N` sends every row after N (`LiveSocket.cs:46-52`). `RemoteFollower` copies rows contiguously (`hub.PublishCopy` returns false on a gap, `RemoteFollower.cs:116`, `LiveHub.cs:44`). So a long remote catch-up on the socket needs a `rows/page` loop or a bigger catch-up; neither is wired for the follower. assumed (design not read beyond the registrations; the gap itself is verified in the lines cited)
