Controlled extension experiment · 2026-08-03

Reuse extensions selectively. Keep Rust as the authority.

Implementation results for Houston, Monaco DiffEditor, the VS Code SCM API, GitLens, and Git Graph in the existing Tauri/Svelte app.

Result: the hybrid architecture works. Declarative extension contributions and editor APIs fit cleanly; desktop-oriented extensions should not be allowed to introduce a second Git/process stack.
Working

Official Houston theme

The exact theme JSON is registered once in the existing local web extension host. The old prototype color overrides are removed when Houston is active, preventing the theme from flashing and reverting.

Working

Native Monaco diff

The selected Git change opens a real side-by-side DiffEditor with distinct file:// models. Rust supplies bounded original and modified text; binary and oversized files retain the safe fallback.

Read-only proof

VS Code SCM API

The app's already-loaded Rust Git state can be projected through vscode.scm.createSourceControl. Stage and commit commands remain on the existing source-control panel until command forwarding is deliberately wired.

Whole extension or API?

The controlled spikes produced a clear boundary.

FeatureMethod usedOutcomeWhy
HoustonDeclarative extension contributionKeepTheme JSON is browser-safe and needs no extension Node process. The mascot/webview entrypoint is intentionally excluded.
Diff viewerMonaco APIKeepThe app already owns both Git revisions, model lifecycle, tabs, and workspace routing. A full diff extension adds no value.
Source controlVS Code SCM API over existing storeContinue narrowlyStandard API shape without a second Git implementation. Import must stay behind the browser/runtime boundary so ordinary Node tests do not load VS Code CSS/services.
GitLensManifest/runtime compatibility evaluationDo not install yetIt has a browser entry, but its views, storage, repository-provider, authentication, and workbench assumptions exceed the current editor-service host. Full value would require enabling a much larger workbench surface.
Git GraphManifest/license compatibility evaluationDo not embedIts extension is workspace/Node oriented, has no browser entry, expects Git execution, and is a poor redistribution fit. Keep the existing Rust history model.

Concrete changes

Curated runtime

  • extensionCatalog.ts is the allowlist.
  • extensionRuntime.ts registers contributions exactly once.
  • rustGitScmProvider.ts projects active-workspace Git state without executing Git.

Diff data path

  • git_diff_models.rs obtains bounded text models.
  • NativeGitDiffEditor.svelte owns and disposes paired Monaco models.
  • GitDiffView.svelte preserves the unified fallback.

Theme ownership

  • The official Houston asset is pinned with its license.
  • csharpLanguageClient.ts starts the singleton extension runtime first.
  • Legacy color customizations are cleared whenever Houston owns the editor.

Rust translated for a .NET developer

git_diff_models.rs is an internal service class split out of the Tauri composition root. Its functions return DTO data; Option<String> is equivalent to nullable string?; the 512 KiB guard is input validation at the native boundary. JavaScript never receives arbitrary process execution—only validated results from named commands.
